This looks like the shared-FS concurrent-load deadlock the skill doc warns about under rule 5, but the scheduler has no notion of it: it will happily place N model-loading jobs at once on N nodes that all read the same Lustre path. Suggestion: an optional per-pool concurrency cap on dispatch (e.g. stagger dispatches by ~60s, or a 'max_concurrent_starts' knob), so a full-pool fan-out does not self-deadlock.
